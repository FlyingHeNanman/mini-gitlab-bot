## 验证中发现并修复的真问题

| 问题 | 修复 |
| --- | --- |
| 新项目没有任何机器人标签时，sweep 直接 `add_labels` 会因 `状态：已解决` 不存在而失败；而 sweep 可能先于任何 triage 运行 | `Sweeper` 增加 `LabelEnsurer`，每项目首次扫描先幂等创建 32 个固定标签；新增单测 |
| 真 GitLab 的 tag API 对象没有顶层 `web_url`（只有 `commit.web_url`），导致 `build_compare_url` 拿不到 base，Release 正文缺 compare 链接 | `_tag_info` 从 `commit.web_url` 推导 `/-/tags/<name>`；HTTP 桩改为真实形状并加断言 |

## 默认 autoclose 的行为差异（未改代码）

GitLab 默认 `autoclose_referenced_issues=true`：带 `Closes #N` 的提交推到默认分支后，
**GitLab 会先自动关闭 issue**。此时 sweep 的 `list_open_issues` 看不到它，机器人不会回帖/打标签。

- 首次验证（未关闭 autoclose）实测：issue 已 closed、标签为空、无机器人评论、`sweep_resolved_total=0`。
- 关闭项目设置 `autoclose_referenced_issues` 后，19/19 项通过。

生产使用前需要二选一：

1. 在目标 GitLab 项目关闭 autoclose（`Settings → Repository` 或 API `PUT /projects/:id`）；
2. 后续让 sweep 扫「近期 closed 且被 commit 引用」的 issue，补回帖/标签（需要新增 SCM 方法与状态判断）。
